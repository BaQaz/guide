全体の流れ

  1. 上から順に、印の付いたカードをコピーして送るだけです。「次はこれ」が付いたカードが、次に送るものです
  2. 0. 途中で止まった作業 → 1. 記事 → 2. エピソード → 3. 装飾 → 4. 写真 → 5. 選手カード → 6. 製作者ページ の順。2 と 3・4 は同じ記事を書き換えるので、2 をマージしてから 3・4 を回す
  3. いまの残り：記事 書かれていない記事はありません。／エピソード 残り 30 本・3 チャット。／装飾 残り 1 本・1 チャット。／写真 残り 178 本・12 チャット。／選手 残りはありません。
  4. GPT の作業が終わったら「7. PR をまとめてマージ」を送る。マージされると1〜2分でこのページが作り直され、終わったカードが消える

反映のしかた（どの作業のあとも同じ）

  1. ChatGPT がブランチにコミットして PR を作る（チャットに PR の URL が返ってくる）
  2. 新しいチャットで「2. PR をまとめてマージ」を送る。PR がいくつあっても1回でよい
  3. マージされると、GitHub Actions が1〜2分でサイトとこのページを作り直す（Actions の画面で緑のチェックになれば完了）
  4. サイトとこのページを再読み込みする。書き終わった分はこのページから消え、残りの分だけが並ぶ。疑問を増やしたときは、新しい疑問の記事プロンプトがここに出る

Pages への反映は、さらに1分ほど遅れることがあります。変わらないときは少し待ってから再読み込みしてください。

ChatGPT の準備（毎回）

  • 1プロンプトにつき新しいチャットを1つ。モデルは考える系（Thinking）、ウェブ検索と GitHub への書き込み（BaQaz/guide）を使える状態にする
  • 書き込みの確認を求められたら許可する。途中で止まったら「続き」と送る（コミット済みの次から再開します）
  • 急ぐときは、送るときに「ブランチは作らず main に直接コミットしてください。PR も不要です」と一言添えると、書いたそばから反映されます（レビューなし）

11. 公開（GitHub Pages）

  1. Settings → General → いちばん下の Danger Zone →「Change repository visibility」→「Make public」（無料プランでは Pages に必要。リポジトリの中身は誰でも見られるようになる）
  2. Settings → Pages →「Source」を「Deploy from a branch」、Branch を「main」「/ (root)」にして Save
  3. 1〜2分後、サイトは baqaz.github.io/guide/site/、このページは baqaz.github.io/guide/docs/gpt-prompts.html で開けます。マージのたびに自動で最新になるので、ダウンロードは不要です

スマホで GitHub の Settings が見当たらないときは、ブラウザのメニューで「デスクトップ用サイト」に切り替えます。

12. 球場で使う

  • トップ：速報ボード（スコア・B/S/O・塁）とスタメン。ランプと塁はタップで変えられます
  • 写真で更新：速報ボードの「写真からスコアとスタメンを更新」→ プロンプトをコピー → ChatGPT に写真と一緒に送る → 返ってきたコードブロックの中身を貼って「反映」。この更新はその端末のブラウザの中だけに保存されます
  • もっと知りたいとき：記事の見出しごとの「GPTに聞く」でプロンプトがコピーされるので、ChatGPT に貼るだけ
  • 電波が弱いことがあるので、試合前に一度開いてタブを残しておく
